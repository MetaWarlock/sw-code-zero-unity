- РЕЗУЛЬТАТ (смена 83). Физический NT-stream **измерен** трассой записей `$2000–$2008` (write-watch по `$2006`/`$2007`, писатели только `$C121`/`$C127`/`$C130`): один шаг курсора `$25` = 2 тайловые колонки × 4 строки имён + ровно 1 байт атрибута; `band = ($25>>3)&15`, `rg = $25&7`, `page = $25>>7`; имя = `page*$400 + (rg*4+i)*32 + band*2 + j`, атрибут = `page*$400 + $3C0 + rg*8 + (band>>1)`. 128 шагов на страницу, 256 — кольцо двух страниц; окно f282..290 (136 шагов при `$0F=136`) заканчивается хвостом `$2400…$25A0` = полоса 0 страницы 1 — арифметика сходится по всем прогонам, в м1 и городе окно побайтово равно. Правки `LevelTileMap` **не делалось**: связь «полоса → колонки мира» (адрес источника в `$E698`) ещё не выведена, поэтому смена страницы 1 была бы подгонкой под запись.
- БЛОКЕР (первый причинный город, запись `20261019T212535Z`). Оригинал детерминирован 2/2 и завершён (`$31=08` f27890, карта f28810/f28911, очки `7070707679`); порт побитово точен до f6388 включительно. Первый diverge — RNG-группа на poll 6387 (f6388). Механизм установлен точно: NMI повышает слот процесса только из состояния `$01` (`$C0AC CMP #$01`); если опрос ловит CPU внутри обхода `$8000` (`$80=02`, `$9A=01`, `$96`=13…15, `$97` = незавершённая сборка OAM), следующий кадр не входит в frame-engine и `$95`/`$E4` стоят. Сменой 84 класс закрыт по всей записи: **12** таких кадров, ложных срабатываний нет, в м1 — 0 ⇒ требование к порту узкое и проверяемое: потерять ровно эти 12 входов и ничего больше. Остальные 1498 из 1510 стоячих `$95` в городе — фазы, где frame-engine вообще не работает (титул/карта/загрузчик), и порт их уже воспроизводит побитово. `$92` шагает 1/кадр, `$F0/$F5/$F6` и очередь `$DC…$E3` не при чём. Атрибуции смен 80 (`$80=02` на момент NMI) и 81 («`$9A` подавляет ветку NMI», «чистый тайминг inline-цикла `$DE86`») **опровергнуты**. Причина незавершения обхода — бюджет CPU-циклов кадра, модель в порту отсутствует; трасса `cpu.cycleCount` для этой задачи **не годится**: интервал между первыми записями `$95` соседних опросов = 29,450–29,875 циклов на обычных кадрах и 37,791–41,019 на серии 6383…6400 вокруг первого держания, но без держаний разброс доходит до 28,468–32,721 ⇒ фаза записи внутри кадра плавает, и «обход `$8000` дороже кадра» этой метрикой не доказывается; нужен счётчик циклов по самому обходу.
