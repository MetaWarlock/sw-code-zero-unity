## КОНТЕКСТ ПРЕДЫДУЩИХ СМЕН (закрытое; актуальный «СЛЕДУЮЩИЙ ШАГ» — в конце файла)

М4/крюк закрыт: `PhysCompare.Hook` = 298/298 (золотой захват `gold_hook_ride2`, сид f1),
Walk/Jump = 119/119. Причина последнего расхода найдена и перенесена: гейт
`$CD3E…$CD54` (`$F5FC` безусловно пишет скорость `$FF,$AB`, когда целая часть 0..$04
и A не удерживается) выполняется ДО ветвления `$F2E5` по знаку, поэтому первый кадр
воздуха после отпускания идёт по ветке падения и не делает проверку потолка.

G18(б) закрыт дизассемблированием, а не выводом из рейда: `$8049–$805A` вычитает
`$0510-$FA`, и при заёме `$8051 SBC #$0F` выполняется со сброшенным C (−$10), после чего
`$8053 CLC` переносит этот заём в побайтовое сравнение строк `$0520-$FB` (−1 строка).
Поэтому рейд `$0520=2`, `$FB=1`, `$0510<$FA` даёт `2−1−1 = 0` → на экране честно;
приблизительный гейт `ScrollMode != 0` удалён из `OamDispatcher.UpdateSlotCull`, а
смерть слота 0 требует разницы строк ровно 1 (`PLA / CMP #$01`). Заодно: `$80C6 RTS`
при горизонтальном уходе не продвигает анимацию — в порту это упрощение осталось.
После изменения пересчитаны все три сравнения: Hook 298/298, Walk 119/119, Jump 119/119.

G18(а) остаётся гипотезой (порядок кадра: машина состояний ДО сервиса крюка/скролла,
восстановлено по f1/f80/f81) — прямого подтверждения вне рейда пока нет.

Приёмка рендера перепроверена после правки кулла (2026-10-14, харнесс найден и записан):
