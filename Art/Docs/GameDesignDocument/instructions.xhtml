Правила документации GDD

GDD · Правила проекта · Beholder ZERO

Формат и оформление

Документация хранится в Art/Docs в UTF-8, в формате XHTML 1.0 Strict. Это корректный XML в namespace XHTML: закрытые теги, кавычки у атрибутов, экранирование & и <. Общий стиль — documentation.css.

Использовать стандартные h1–h6, p, ul/ol/li, dl/dt/dd, table/caption/thead/tbody/tr/th/td, pre/code, blockquote, img и a. Атрибуты class, style, обработчики событий, script и произвольные элементы запрещены. CSS оформляет теги и структуру. Уникальные id нужны для якорей.

Доказательства

Для механики указывать поведение, условия, входы/выходы, исключения и свидетельство: ROM с банком/адресом, кадр, запись или контракт. Факты, гипотезы и наблюдения человека различать явно. NES-объект, анимация, PRG/CHR и иллюстрация — разные сущности; соответствие проверяется отдельно. Ресурсы иллюстраций сохраняются рядом в sprites/; экспортёр переиспользуется.

Очередь и проверка

ZERO-34 содержала справку существующего GDD, а не определённую новую задачу; сведения возвращены в README.xhtml. Текущие планы, назначения и следующие действия — только в трекере. В статье остаются спецификация, факты и ссылки. Наличие статьи не означает приёмку игры.

Проверять XML, локальную Strict DTD, отсутствие class/style, ссылки и читаемость в браузере. Команда из корня: bundled Python → Art/Tools/DarkwingResearch/project_layout.py validate. Путь bundled runtime получать через load_workspace_dependencies. Каталог: инструменты.
