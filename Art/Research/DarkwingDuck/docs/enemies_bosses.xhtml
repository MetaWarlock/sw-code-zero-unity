Darkwing Duck (NES) — Enemy & Boss Behavior Catalog

Reverse-engineered from prg.bin (banks 0-7; bank N at file offset N*0x4000). Generated 2026-10-11 by the enemy/boss research agent. Companion files: object_catalog.csv (per placed type), labels_enemies.json (named addresses). Related: docs/player_mechanics.md (player states, weapons), docs/game_flow.md, FACTS.md.

All addresses are CPU addresses. Bank 6 ($8000-$BFFF when switched) holds the enemy/gas behavior code; bank 1 holds the boss code; both are dispatched from the per-frame main loop $C9AC (bank 7) in the order: enemies → bosses → object update.

1. Dispatch architecture

1.1 Enemy dispatch — bank 6 $8000 (Enemy6_Dispatch)

$99 = $40            ; gravity fraction for this frame (same value set by boss dispatch)
X = 1 .. 15          ; object slots (0 = player)
loop per slot:
  $04D0,X bit7 clear            -> skip (inactive)
  Y = $04E0,X (behavior id)
  id >= $47                     -> skip (bank-1 boss dispatch handles these)
  target = $825F[Y] | $82A7[Y]<<8   ; jump tables, bank 6
  push fake return $8027, JMP target
$8027: INC $4D ... next slot

1.2 Per-slot post-processing (bank 6 $8032-$816C, runs before each behavior)

  1. $803C hit-flash: if $04C0,X (flash timer) != 0: toggle $0400,X bit $08 (sprite visible bit) from bit 3 of the timer, DEC $04C0,X. $04C0 = $0F is set whenever an enemy takes a gas hit.
  2. $8066 JSR $FAAE — player-projectile overlap (see §6). If a projectile overlaps:
    • ids $1E/$34 (falling spikes): only take hits while below the player top (custom check $8079).
    • $8096 weapon damage: SFX $1D (hit), then DEC $05A0,X by weapon power taken from the projectile's anim number $0420,Y (Y = projectile slot $0F):
      projectile anim damage
      $13 $14 $16 $19 $1A 1
      $18 2
      $17 $29 3
      HP ≤ 0 → $80F2 death. Otherwise $04C0,X = $0F (flash), spawn hit-puff
      ($F872 = object anim $14, behavior 0), JSR $F872/$F872.
    • $80F2 death: $04D0,X = $80 (keep active, clear state), $0590,X = $FF, $04E0,X = $05 (death-pop behavior), rise velocity $0550,X = $44 / $0560,X = $03, SFX $1E (enemy destroyed). Behavior $05 ($86A2) then pops the corpse up, spawns 1-2 debris (behavior $0A, $8715, velocities from RNG table $87A2/$87C2), falls off screen.
    • Special deaths $81C0: ids {0F,17,1D,2A,30,32,34,42} don't explode; when killed by the thunder/strong projectile (player anim $14/$16) they are converted: cleared, or re-tasked to behavior $1F ($8812 "friendly", pops up and falls) — gas-lingers that touched them become pickups via $08.
  3. $813B enemy→player contact: skipped while $7C != 0 (player invuln timer) or JSR $FB7B says not touching. If touching: SFX $15, $7C = $3C (60 frames), JSR $F9C2 (player hurt/knockback). Special anim ids ($40 $4E $9F $7D $62 $55 $A6) do a distance check ($F928 |dx| < 8) and can instead bounce the player (SFX $1A, retask enemy to behavior $06) — spiky armor enemies.

3. Object type catalog (placed types)

See object_catalog.csv for all 105 types. Data sources:

  • Spawn: bank 4 $8090 (spawner) → $80FC spawn routine. Placement arrays are five parallel lists (screenX, localX, screenY, localY, type) pointed to by $72/$74/$76/$78/$7A.
  • Type tables (bank 4): $8AB3 — 105 records × 4 bytes [flags, behaviorId, animId, param] → loaded to $0400,X / $04E0,X / $0420,X / $0570,X; and $8C57 — 105 × 4 bytes, first byte = starting HP → $05A0,X. Both tables are exactly 105 entries ($8AB3-$8C56, $8C57-$8E56) matching the 105 placed ids from manifest.json.
  • $0570,X param: low 5 bits = touch-class index into the hitbox tables (§6); upper bits are reused as scratch by behaviors. $0400 flags: bit7 = active/on-screen, bit6 = h-flip, bit4 = overlap-calc path, bit3 = hit-blink clear, bit2 = "projectiles pass through" (checked at $FAE4).
  • HP $05A0 semantics: $80 (128) = gas-immune (bosses); 0 = dies to one hit; 1-15 = normal enemies (flamethrowers 13/9, heavy shooter type 33 = 10, type 100 = 15).
  • Type $FF (255) appears in placement arrays as the terminator/empty marker, not an object.
  • Never placed but defined: types 20, 22, 55, 63, 100 (rows flagged NEVER_PLACED in the CSV).

Field notes for slots (verified): $0410/$0430 anim frame/timer, $0420 anim id, $0440/$0450 screen Y/X, $0460 Y subpixel accumulator, $0480/$0490/$04A0/$04B0 behavior-local timers/counters (frequently double as HP), $04C0 hit-flash timer, $04D0 bit7 active + low nibble state, $04E0 behavior id, $04F0/$0500 abs X (px/subpx), $0510/$0520 abs Y, $0530/$0540 Y vel int/frac (up-positive), $0550/$0560 Y vel int/frac, $0570 param/touch class, $0580 direction (bit0 right, bit1 left, bits2-3 flip), $0590 placement index ($FF = not placed), $05A0 HP.

4. RNG

No single LFSR. The generator is a set of four zero-page counters $E4 $E5 $E6 $E7 (RAM, zero at power-on) advanced in place at each use site with the canonical step state[i] += state[i-1] + carry, then masked by the caller:

LDA $E4 / CLC-ish / ADC $E5 / STA $E5        ; E5 += E4+C   (most common; e.g. $8D2A, $94FA, $940D, $A03C, $A7AB, $A864, $AF74, $B119)
LDA $E4 / ADC $E6 / STA $E6                  ; E6 += E4+C   ($AF0F, $9613 variant)
LDA $E6 / ADC $E7 / STA $E7                  ; E7 += E6+C   ($AA69, $AAB7, $9EE9-region)
LDA $E4 / ADC $E5 / SBC $E6 / STA $E4 / EOR $E7 / STA $E6   ; mixed ($9613-961D, Quackerjack)
LDA $E4 / ADC $E5 / SBC $0490,X / STA $E5    ; perturbed ($A7AB, Bushroot)
LDA $E4 / ADC $E5 / EOR $04F0 / STA $E4 / STA $E6           ; ($9447, orb spawner)
INC $E6 / INC $E7                            ; cheap bump (bank 6 $BAD0)

All sites were found by scanning every bank for opcodes touching $E4-$E7 (see Art/Tools/DarkwingResearch output in the run log): 8× ADC E5 sites, 2× ADC E7, 1× ADC E4, 1× ADC E6, 1× INC E6/E7 pair. Seed: RAM init (all zero); state is therefore deterministic per run and advances only when one of these sites executes (no per-frame tick found). Typical consumption: AND #$03/$07/$0F/$1F → table index (drop tables, attack pattern choice, geyser columns, hop selection).

Call-site classes: boss attack pattern choice (Wolfduck $99EE, Megavolt $AA69, Liquidator $9F43, Bushroot $A686, orb spawner $9440, Steelbeak $AF74), Moliarty hop decisions, enemy flash timers ($8D2A, $94FA, $9648), death debris velocities ($8715), flamethrower shot aim (uses $F93F sectors, not RNG).

5. Enemy ↔ player contact

5.1 Pairing rule $F612/$F64A (push-out, called from player state handlers)

Y = X EOR 1     ; the partner slot — with X = 0 (player) this is slot 1

Both slots must be active ($04D0 bit7), on-screen ($0400 bit7) and partner behavior $04E0,Y != 0. $F699 computes |dx| (16-bit; uses $0400,X bit4 to pick which slot is the reference), $F6DF |dy|. Horizontal push applies when overlap < $11 (17 px), vertical when < $18/$19 (24/25 px) — the returned value is the penetration depth used to push the player out (clamped; see player_mechanics.md §contact). Called from player walk ($F20B), crouch ($D018/$D0B8), air ($D6B1), hurt ($D1AE), transport ($D59F), fall ($F3D2). With X=0 the practical pair is (player, slot 1); other even/odd pairs (2,3) (4,5)… would only matter if the player occupied those slots, so in practice this is the player-vs-one-enemy push.

5.2 Projectile → enemy damage $FAAE/$FB08

For projectile slots Y = 4..1: both active + on-screen, projectile behavior != $1F, enemy behavior not in {0..4}, enemy on-screen, enemy $0400,X bit2 clear. Then $FB08: |dx| < XSize[$0570,X & $1F] and |dy| < YSize[...] → CC = hit.

5.3 Enemy → player touch $FB7B

Guards: player state != $07/$0F, player active, enemy active + on-screen, enemy behavior != $07, $0570,X != 0 (touch class 0 = no touch). Y-half-height from $FBE9[class] (reduced by 8 if player anim is climb $06/$07), X-half-width from $FC09[class]. CC = touching → hurt path (SFX $15, $7C=$3C, $F9C2).
