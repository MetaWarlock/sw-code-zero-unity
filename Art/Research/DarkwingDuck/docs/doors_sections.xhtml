Двери и переходы секций ($E388) — спецификация

Источник: дизассемблирование банка 7 (фиксированный $C000–$FFFF), файл disasm/bank7_E388.txt (disasm/flat_bank7.txt:4818-4935), плюс банк 1 $96C9. disasm/bank4_E388.txt — НЕ код: в банке 4 на этом адресе данные, использовать нельзя. Метки расходятся: labels_level.json → DoorCheckpointLoad, labels_flow.json → LoadMapSubScene; обе частично верны (§6).

1. $E388 = загрузчик секции, X = id секции

  • E388 STX $10 (сохранить id) → E38A JSR $C248 → гашение $C276 ($0F=$10, $0D=$00)
    • очистка слотов $C235 + аудио $C21E → E38D LDX $10 восстановить id.
  • 10 таблиц банка 7, индекс X (E38F-E3BD):
адрес таблицы назначение в RAM
$E497,X стартовый id ячейки $22, $23
$E4C1,X стартовая строка камеры / high Y $FB, $0520
$E4EB,X стартовый scroll X / abs X hi $FD, $0500
$E515,X требуемый CHR0 банк $1A
$E53F,X требуемый CHR1 банк $1B
$E5E7,X банк тайлсета $36
$E5BD,X неизвестно $3D
$E611,X событие кольца $DC[8] ($F84E) $D9
$E569,X → JSR $C2F9 BG-палитра, 16 байт из $C3xx/$5D $0300+$0320
$E593,X → JSR $C319 sprite-палитра, 8+8 байт из $C4FD/$C505[id*8] $0310/$0330
  • Размер таблиц 42 байта (id 0–41); запись id 0 — заглушка $C2, т.е. максимальный id $29 из объектного пути влазит ровно.
  • E3C2-E3D3: $3E=$3F=$EE=$ED=0, $0510=$06, $04F0=$30 → спавн (table:$30, table:$06).
  • E3E8 STA $5B=0 (сброс запроса) → E3EA JSR $DE24 (сброс состояния, §4) → E3ED JSR $FF06 (yield) → E3F0 A=$2C; JSR $FA78 ($0420=$2C, $0430=0, $0410=0) → E3F5-E3FC $04D0=$80, $0400=$D0 (то же, что $DD57) → E401 LDX#0; JSR $F5FC ($0550=$AB, $0560=$FF) → E406 $50=$12.
  • E408 если $5D≠0: JSR $C850 (18 байт $C8CF → $05B0); далее E40F ветвление по $54: 1 → $05BA=$7A, 2 → $7B, 3 → $7C (все trio $05BC=$7D); 0/иначе → E43D JSR $C887, $05BE=$05C0=0. Затем E44A $5D=0, E44C $53=0, E44E JSR $C158 (включить рендер, $2001=$1E, $FE=$1E).
  • E454: если $6D ∈ {2,4,6,8,$A,$C,$E} → $3B=$78.
  • E478: если $6D ∈ {4,6,8,$A,$C,$E} → JMP $C25F (PRG=4, JSR $9800 — внутренний движок), иначе E492 JMP $C254 (PRG=5, JSR $8000). Не возвращаются, оба уходят в $C270.

2. Триггер двери со стороны игрока ($EB52 → $EBC8)

  • $EB52 пробирает метатайлы типом через $EBE8 (карта $0600, маски $ECA9/$ECAD/$ED19), максимум в $10 (EB6E-EB72).
  • Хвост: EBAA CPX #$01 → EBAE LDA $10 / EBB0 CMP #$05 / EBB2 BEQ $EBC8 — только слот 0 (игрок), тип метатайла 5 = «выход здесь».
  • EBC8 LDA $0500,X (abs X hi = колонка) SEC; EBCB SBC $FD; CLC; EBCF ADC $22; EBD1 TAY; EBD2 LDA ($34),Y; EBD4 AND #$1F; EBD6 STA $5B; EBD8 STA $6D; EBDA RTS.

Итого: id двери = биты 0–4 скрипт-байта текущей ячейки (массив $E18C-семейства); бит 6 = горизонтальный скролл, бит 7 = Y-snap (см. player_mechanics.md). Разделения битов нет — просто AND #$1F (level_format.md §3/§9 закрыты этим же выводом). Назначение = $E497/$E4C1/$E4EB[id], т.е. $22 = $FB*$2E + $FD (проверено: id1 0x19=117+8, id6 0x31=217+15, id7 0x4B=710+5, id16 0x33=317+0, id28 0x6E=11*10+0). $E388 не трогает $32/$33/$34/$35 и не меняет $2E → сменить мир (набор комнат) он не может; это делает $DD57.

3. Второй источник id: объекты «дверь выхода миссии»

Банк 1 $96C9, поведения $7C/$7D (уже портированы как MissionDoor, EnemyBehaviors.cs:4302): 96F1 LDA $04E0,X; AND #$0F; TAY; 96F7 LDA $970C,Y → $5B; 96FC LDA $971A,Y → $9C; 9701 LDA $9728,Y → $66. $970C = {0F, 11, …, 29}, $971A = {10, 12, …, 2A} (смещения файла банка 1 0x170C/0x171A; третья таблица на 0x1728). $93CF переставляет $9C → $5B и обнуляет $66. Потребители $5B только два: CA6E LDX $5B / CA72 JSR $E388 и D461 LDA $6D; AND #$1F; TAX; D466 JSR $E388 (респаун после смерти $D41B). Смерть/победа двери: SFX $23, состояние игрока $14, слот убивается; результат ($F8 бит 7) решается позже (game_flow.md §4).

4. Что делает $DE24 (сброс состояния игрока/камеры)

JSR $C14E (рендер выкл, $2001=0), повторно JSR $C235, $52=$20=$2B=$2F=1, $21=4, $FC=0, $FA=0, обнуляет $28,$29,$70,$71,$5F,$56,$57,$64,$58,$5A,$5C,$ED,$EE,$5E,$50, $63,$65,$9B,$3B,$9D,$F8,$9E,$98 (обратить внимание: $F8=0 — флаг результата), затем $25 = ($FD ROR ROR) & $80, $0F = ($25 ^ $80) | $08, $05=1, DE8A JSR $E698 в цикле до $25 == $0F. $E698 собирает 4 записи очереди VRAM ($0360–$0377) из $EB17,X/$EB1F,X + упаковка бита $25, E703 LDY $23; JSR $EB27 (указатель комнаты) ; JSR $EA36 (раскрытие метатайлов), патчит из обратного чтения PPU $0140,X; сбрасывается через $C119. $E7C6 (перерисовка строки) вызывается только из скролл-кода DCC1/DD14; $E63C — только из DC14/DC67. Переключения банков внутри загрузки: $FF55 PRG=4 на $DE99, затем JSR $8040, $8090 (фидер/спавнер банка 4); в хвосте движок выбирает PRG=5 ($C254) или PRG=4 ($C25F). CHR: пишутся только $1A/$1B, применяет их NMI (SetCHR0 $FF21 / SetCHR1 $FF3B).

5. Checkpoints и завершение уровня

$6D — одновременно «текущий id секции» и последняя дверь (EBD8); используется для выбора движка (E454/E478) и респауна (D461-D466). На зачистке уровня сбрасывается: $D4B3 обнуляет $5D/$54/$60/$61/$6B/$6D, затем INC $38. Промежуточных чекпойнтов внутри уровня нет: D4E9 перечитывает $31 из стартовой ячейки $DEB9 (кормит $6D также $DB27, PlayerCore.cs checkpoint-feed).

6. Расхождения документов с дизассемблированием

  • level_format.md §3/§9: нет разделения битов, AND #$1F на $EBD4; $6D = сам id двери, отдельной таблицы чекпойнтов нет.
  • game_flow.md §1 (последняя строка: «$E388 — та же структура для подсцен карты») занижает: $E388 — также загрузчик дверей выхода миссии/боссов (id $0F–$29 из $970C), и он не перезагружает $32/$34/$2E, значит не меняет миры — это $DD57.
  • game_flow.md §5 «$6D = ожидающая загрузка подсцены карты» неточно: запрос лежит в $5B, а $6D — липкий id для выбора движка/респауна.
