Darkwing Duck (NES) — Player Mechanics (static reverse, addresses + constants)

Scope: player (object slot 0) movement, physics, collisions, hook/hang, gas gun, damage, animations. All CPU addresses are as executed in game (fixed bank = PRG bank 7 at $C000-$FFFF; switchable $8000-$BFFF = bank noted per label). File offset = bank*0x4000 + (addr - base), base $8000 for banks 0-6, $C000 for bank 7.

0. Corrections to previously "established" context

  • The NMI bank-queue task (NMI $C0F6: JSR $8000) runs the audio driver in PRG bank 3 (bank3 $8000 = JMP $806C; $8393 = note processing, $8684/$86BA/$8023 = tempo/envelope helpers, $80EC = STA $4000,Y APU write). The earlier claim that bank5 $8393/$8684 are "per-object animation advance / sprite composition" is wrong — those are audio.
  • Player animation + OAM composition is bank5 $8000-$81F7 ($802F per-slot: culling $802F-$80C6, player invuln blink $80E1-$80F1, anim advance $8100-$8141, OAM composition $8143-$81F7). It runs every frame from the master loop.
  • Bank 4 $9800 is a near-copy of bank5 $8000 (same object update; differs only in JSR targets $982F and anim tables $B222/$B292 instead of $B429/$B4F0). Only screens whose level-script byte is $34/$56/$76/$97/$B5/$98 use the bank4 copy ($CAC5); all others use bank5 ($CAAF). Bank4 $9800 was never executed in the 120-frame mission-1 trace.
  • Bank 2 is not only menus: the frame task loop at bank2 $A400 runs the briefing/level intro (loops until A/B/Left/Right pressed, $A414: AND #$C3), and the fixed-bank master gameplay loop is $C9AC.

1. Per-frame flow (master process, fixed bank)

$C9AC Player_MainLoop (loops via $CAE4 JMP $C9AC, yields each frame with $FF06):

  1. $C9AC: $65 negative → skip to $CAD8 (level inactive).

  4. $CA40 JSR $CAFC Player_DeathCheck: if slot0 active ($04D0 bit7) → $CB41 Player_StateDispatch; else energy/HUD drain $CB01-$CB3E (see §7) then $D41B.
  5. $CB41 Player_StateDispatch: X=0; every frame re-arms walk velocity $0530=$80, $0540=$01 ($CB43-$CB4C); dispatches JMP ($CB5F+Y)($CB75+Y), Y = $50 & $1F (player state machine id, see §2).
  6. $CA59 JSR $DA70 Player_CameraFollow: horizontal dead-zone follow; screen X of player $00 = $04F0-$FC; scroll right ($DC19, $2F=2) while $00 >= $10 (and $00 < $88), scroll left ($DBCE, $2F=1) while $00 >= $89/< $F1; after scrolling the player is pushed 16 px ($DABD-$DACC, $DAEE-$DAFA).   7. $DAFD Player_ScriptCheckpointHook: reads level script byte ($34),Y (Y=$22 = current screen column): byte $C1-$CF odd → checkpoint $6D = byte; low nibble == 1 → hook column (see §5); nibble == 2 → vertical scroll snap $DB3F-$DB6C.
  8. $CA5C: $6E/$6F = $04F0/$0500 (player prev X, used by collision clamps).
  9. bank4 $8090: level object spawner (layout pointers $72/$74/$76/$78, occupancy $0340, spawns into slots 15..4, sets $04E0 behavior/$0420 anim/$05A0 etc.).
  10. $E388 if $5B != 0 (door/level-event loader, §5); $EDF1 (area palette/CHR by $31); $EFBE (palette animation).
  11. bank6 $8000 = enemy behavior dispatch (slots 1-15, ids < $47, table $825F/$82A7); also sets $99 = $40. bank1 $8800 = boss dispatch (ids >= $47, table $8836/$88B6); also $99 = $40. $99 = gravity fraction = $40 every frame (§3).

Input: read on every process resume at $C162 (labelled Slot0_ResumeHook; called from $FEC7 Process_ResumeRunning → so exactly once per frame per process). $16 = held, $14 = pressed edge; bits 7=A, 6=B, 5=Select, 4=Start, 3=Up, 2=Down, 1=Left, 0=Right (verified from read order at $C16D-$C180).

3. Physics — exact constants

Coordinate/velocity format: positions are 16.8 fixed point: X = $04F0 (int lo) / $0500 (hi) with fraction accumulator $0470; Y = $0510/$0520 with fraction accumulator $0460 (slot 0). X grows rightward; Y grows downward (screen Y = $0510 - $FA mod $F0, $8049-$8054). Velocities are signed 8.8: integer byte + fraction byte (e.g. $0540 = X vel int, $0530 = X vel frac; $0560 = Y vel "up-int", $0550 = frac). Vertical integration subtracts the velocity from Y ($F5A4 adds when falling, i.e. negative velocity), so positive $0560 = upward motion.

Jump height ≈ v²/2g = 4.8945²/0.5 ≈ 48 px (~3 tiles), apex ≈ 20 frames after takeoff. Short hop: releasing A immediately → rise of ≈ (4.89² − 0.33²)/(2·0.25) frames-worth… precisely the cut zeroes ascent within 1 frame, minimum hop ≈ 13-14 px.

Turnaround: none — direction changes are instantaneous (both integrators share the same velocity registers; the facing flag $0400 bit6 flips immediately, $F24B/$F2A6).

5. Hook (peg) grab / hang / ride

  • The level script byte ($34),Y per screen column gates everything: low nibble == 1 = hook column; byte $C1-$CF (odd) = checkpoint id → $6D ($DB27).
  • Grab $DB6D Player_HookGrabCheck (called from $DAFD after camera follow, only when scroll X $FC == 0 and script nibble == 1): if $50 != $0C and player screen Y ($0510-$FA) >= $E8 (232) → $DB8B: $50=$0C (hang), $0550=$80/$0560=$00 (0.5 px/frame up), all object slots 15..1 cleared ($DB99-$DBB1), script byte $90 → $0400 |= $20. So Darkwing catches the peg as he descends past the bottom of the screen — there is no "Up near hook" test; it is position + script-column based.
  • Hang state 12 $D7F9: integrates $F539 (0.5/frame rise); anim frame pinning (6→f1, $0D→f1, 4→f2). The camera scroll routines carry the player (script byte $90 sets bit5 again every frame). Release: when scroll Y $FA == 0 → $50=1 (fall).
  • Grabbing also happens from airborne state 11: $D6C4 probe with $40=$3A (hook points above head) feeding $10 into the same land/grab decisions; and type-7/8 tiles set $0400 bit5 which the jump physics treat as ground ($CE08).

6. Damage, knockback, death

Contact detection $F612 (horizontal) / $F64A (vertical): compares the player (slot 0) against its paired slot (X^1) when both active and enemy behavior $04E0 != 0; computes overlap via $F699/$F6DF; result clamped to $10 = min(pen,4). $10 == 4 = full overlap → damage. Spikes produce the same $10==4 from tile probes — identical reaction.

Hurt (fresh hit, $7C==0): $50=6, $51=$0F, anim 9 ($FA29 picks anim $1D/$1C in areas $31==$08 with enemy anim $4D / $31==$0C with $5D), SFX $15, $7C=$3C (60 invincibility frames), then $F9C2 Player_HurtKnockback:

  • saves $58 = $50 (state to restore), forces $50 = 6;
  • writes the flash codes into the dynamic RAM metasprite template $05B0 block: hit1 → $05B4=$82, hit2 → $05B8=$83, hit3 → $05B6=$83, hit4 → $05B2=$82 and death: $7C=0, $50=7, $04D0=$80, anim 9 ($FA1E). 4 hits = death (the HP counter is hidden inside the RAM sprite template bytes $05B2-$05B8).
  • Invuln blink: bank5 $80E1-$80F1 decrements $7C per frame and skips OAM composition when ($95 & 4) == 0 (4 frames invisible / 4 visible).

Knockback flight (state 6 $D2C3): horizontal velocity registers re-set to 0.5 px/frame, first frame $F5FC (fall -0.33), companion slot 5 spawned (template $0A) at player X, Y-$14; per frame: vertical integrate $F2D7 (gravity applies), inverted steering — Right held (bit0=1) → $F254 (moves left, faces right), Left → $F200 — i.e. the player drifts away from the held direction while $52 was latched at hit time; $51 counts $0F → $50=0. State 4 (air hurt) lets you steer facing only, fire (anim $0C), or press A to jump out (anim $0D if Up / $11), Down to drop.

Death paths:

  1. 4-hit ladder (above) → state 7.
  2. Pits/falling out: death throes state 7 $D353 can be entered with $66 (death flag set by level scripts) — $CB41 runs when $04D0 bit7 clear via $CAFC's $66 branch.
  3. Gas energy exhausted: $CB0E-$CB3B / state 7 $D3D9-$D407 drain HUD meters $05E6 then $05E4 (tile codes $70..$79); both empty → INC $64 → $D41B.

Death sequence state 7 $D353: launch up ($0560=2), $0490=$0F frames of rise, $0480=$3C pause (at $1E plays SFX $25 and sets $9B), then falls with gravity; energy drain; → state 8.

State 8 $D41B: if $64 != 0 → game over cinematic ($D46C, bank2 $8D00/$9900, continue counter $5D, then $D95D level restart). Else if $6D == 0 → reset to level entry ($C887 spawn, $50=$12, CHR $D589[$31]). Else respawn at checkpoint: $66 clears, $5D counts deaths, $E388 with X=$6D & $1F reloads the section (respawn position $04F0=$30, $0510=$06, anim $2C, $0400=$D0, state $12).

Lives/continues: $64 = death flag accumulated per life; $5D = deaths at checkpoints; game over → continue screen → level restart (no separate lives counter found; continues are implicit via $5D).
